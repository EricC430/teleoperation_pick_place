## 要回答的問題

相機被碰歪、手臂沒動時，**手臂上和桌上都不放任何標記、不放座標紙、不用尺量**，只用手臂 CAD＋關節讀值＋已量好的 FK 參數，能不能把相機位置找回來？

- 離線結果：有貼標記、手臂參數固定、只解相機時，同一天的資料相機差 4 mm、0.69°（`docs/worklog/2026-10-29_fl_markerless.md` §4）。

## 為什麼疊得好還不夠，以及這次怎麼檢查

疊合度（CAD 投影跟影像的差）就是演算法在最小化的東西，所以最後一定疊得不錯；疊得好不代表相機對。2026-10-29 的例子（`docs/worklog/2026-10-29_fl_markerless.md`）：

- 底座擬合解出 yaw −8.9°，邊緣殘差 0.1–0.5 px，實際上不可能（§2）。
- 手臂參數放開時，兩個解的手臂標記殘差 1.55 vs 1.64 px，相機卻差 1.7 cm、3.1°（§3）。
- 只解相機時殘差 0.94 px，但跟座標紙比還差 4 mm（§4）。

所以分成兩處檢查：

| 要檢查的 | 怎麼檢查 | 在哪做 |
|---|---|---|
| mm 級準確度 | 跟 10/14 照片裡的座標紙 ArUco 比 | 離線，用現有資料，不用到現場 |
| 答案是不是唯一 | 從很多不同起點出發，看是不是都收斂到同一個解 | 這次現場資料 |
| 沒用過的姿勢也疊得好嗎 | 部分照片擬合，剩下的照片只拿來看疊合 | 這次現場資料 |
| 前後一致嗎 | 同一組照片隨機分兩半各算一次 | 這次現場資料 |
| 換一天有沒有變差 | 現場上面三項，跟同一個方法在 10/14 上的結果比 | 現場＋離線 |

現場這三項抓得到「解不穩」和「隨機誤差」，**抓不到所有照片共同的偏差**（例如 §4 那 4 mm）。這種偏差只能靠離線那一項 `推論`。

## 判準（拍之前先定好）

外參的兩個用途（EricC430，2026-10-29）：
1. 讓 sim 裡的手臂跟實機影像對齊。
2. 相機小動之後，不用標記就能重新記錄外參。

依這兩個用途，判準的優先順序如下。

- **主要，保留姿勢的手臂疊合誤差（px）**：用途 1 要的就是這個數字，不需要參考答案。門檻先訂成中位數 ≤ 3 px，跟 ArUco v2 LOO 的 2.35 px 同一級 `推論`。
- **次要，跟座標紙比（離線，10/14）**：只影響桌上物體、桌面在 sim 裡跟影像對不對得上，不影響手臂本身。
- **離線（10/14）**：跟 ArUco 的相機比 ≤ 5 mm、≤ 1°。**已過**：參考相機差 2.0 mm、0.41°（2026-10-29）。
- **現場，唯一性**：所有起點都收斂到同一個解，彼此差 ≤ 1 mm、≤ 0.1°。
- **現場，一致性**：隨機分兩半，相機差 ≤ 5 mm、≤ 1°。
- **現場，保留姿勢**：沒用過的照片疊合誤差，不超過同一個方法在 10/14 上的 1.5 倍。
- 不成立的界線：差 > 1 cm 或 > 2°，或保留姿勢的疊合誤差超過 10/14 的 2 倍。

`推論`：門檻是照離線結果訂的，不是需求規格。如果你有夾取精度的需求，請改成那個數字。

## 現場步驟

**0. 準備**
- `git pull`。用 `scripts/capture_link_markers.py`，10/18 之後沒改過。手臂上沒有標記時，它每一停會印 `arm markers []`，正常。
- `.cache/lerobot/omx_pick_place_pilot_paper_cup_far_wrist_A1` 要在，walk／scan 是沿著這個資料集錄好的路徑走。
- Follower 的 port 以 `configs/teleoperate_omx.yaml` 為準（預設 `COM8`）；變了就加 `--port`。

**1. 清畫面**（之後到第 5 步結束都不能再動）
- 🔴 **手臂上的標記、紙板、膠帶全部拿掉；座標紙和桌上的標記也收走。** CAD 裡沒有這些東西，留著會被當成手臂的形狀。
- 手臂背後和周圍不要放杯子、瓶子、雜物。手和身體在拍照時離開畫面。燈光從頭到尾不變。
- 手臂底下的書和底座不要動。

**2. 手臂回 HOME，先試一集**
```
uv run python scripts/read_joint_pose.py --goto-home --home-episode 10
uv run python scripts/capture_link_markers.py walk --csv calibration/<日期>_fl_cad_before.csv --episodes 14
```
- 打開 `calibration/shots/<日期>_fl_cad_before/` 的幾張照片，確認：
  1. 整支手臂（上臂、前臂、夾爪）大部分在畫面裡。
  2. 手臂跟背景分得出來。

**3. 移動前那組（約 100–150 張）**
```
uv run python scripts/capture_link_markers.py walk --csv calibration/<日期>_fl_cad_before.csv --n-episodes 8 --dry-run
uv run python scripts/capture_link_markers.py walk --csv calibration/<日期>_fl_cad_before.csv --n-episodes 8
uv run python scripts/capture_link_markers.py scan --csv calibration/<日期>_fl_cad_before.csv --n-episodes 4 --pan-to 23
```
- 同一個 CSV 會接著拍；第 2 步拍過的停點如果又被選到，會自動跳過。
- walk 要多拍：手臂的整體輪廓要從很多不同姿勢看，pan 的範圍越廣越好。
  - `推論`：輪廓比對的資訊量比 sub-pixel 角點少，要靠姿勢數量和多樣性補。
- scan 讓夾爪轉不同角度，夾爪的形狀才看得到。`--pan-to 23` 是把 pan 轉到相機那一側（10/14 docstring 的實測：ID6 在 pan +22.9 時 12/12 看得到，−10.5 時 0/12）。

**4. 移動相機**
- 像被碰到那樣動一下 front-left，不用量。
  - 離線的可靠收斂範圍約 2°／1 cm；偏 5°／3 cm 時只有一半收斂。
  - 建議先做一次小的（輕碰一下）。時間夠的話，拍完第 5 步之後再大動一次，然後重複第 5 步（CSV 換成 `_after2`）。這樣能看出現場的收斂範圍。
- 動完整支手臂都還要在畫面裡。
- 🔴 手臂、底座都**不要碰**。手臂**不要斷電**。
- 用一句話記下大概怎麼動的（例如「往右轉一點、往下一點」），只用來對照結果的方向合不合理。

**5. 移動後那組（約 60–100 張）**
```
uv run python scripts/capture_link_markers.py walk --csv calibration/<日期>_fl_cad_after.csv --n-episodes 5
uv run python scripts/capture_link_markers.py scan --csv calibration/<日期>_fl_cad_after.csv --n-episodes 3 --pan-to 23
```
- 回來再用抽樣看最少要幾張。
