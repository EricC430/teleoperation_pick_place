## 1. 這個校正要解什麼問題

LeRobot 錄下來的 `observation.state` / `action` 是**經過校正檔正規化的馬達讀數**；
URDF／模擬裡的關節角是**機構上的關節角**。**沒有任何人讓這兩者對齊過。**

目前模擬把兩者當成同一回事（直接 `math.radians(讀數)`），結果：

- 把真實關節角重播進模擬，夾爪停在物體**正上方約 26 公分**，抓取判定完全不觸發
- 同一份資料裡，夾爪通道整段只變動約 **10 個單位**（47→60），模擬當成 10 度送進去，
  畫面上幾乎看不出開合，但真實影片裡夾爪明顯開合 → **這一路不是零位問題，是比例問題**

**已經排除的解釋**（不要重做這些）：

| 假設 | 怎麼排除的 |
|---|---|
| 符號接反 | 翻 `elbow_flex` 符號後，末端位置與擺放點的 x 相關性從 +0.63 掉到 **−0.34**（反相關） |
| 驅動增益太弱 | 增益從 1× 掃到 20×，誤差**完全不動**；根因是扭矩上限，且已改成運動學重播、增益不再參與 |
| 擺放座標錯 | 修正後水平只差 **2.3 公分**，垂直卻差 11 公分 → 落差是垂直的，不是平面的 |
| 基座高度沒建模 | 已修（基座在桌面上方 15 公分的檯子上）。修完落差**變大**，代表剩下的全在關節映射 |

**所以只剩一個未知數：每個關節的「讀數 → 真實關節角」的仿射轉換。** 這份規格就是去量它。

## 2. 要量什麼（數學先講清楚，才知道為什麼是兩個姿態）

對每個關節 *j*，假設關係是**線性**的：

```
真實關節角(rad) = SCALE_j × 讀數 + OFFSET_j
```

- 一個姿態只有一條方程式 → 只能在「假設 SCALE 已知」的前提下解出 OFFSET
- **兩個姿態給兩條方程式 → SCALE 和 OFFSET 都能解**

這正是為什麼夾爪那一路非量兩個姿態不可：它的 SCALE 幾乎確定不是 `π/180`。

**解法（兩個姿態 A、B）：**

```
SCALE_j  = (真實角_B − 真實角_A) / (讀數_B − 讀數_A)
OFFSET_j = 真實角_A − SCALE_j × 讀數_A
```

⚠️ **兩個姿態要分得夠開**：`|讀數_B − 讀數_A|` 太小，量測誤差會被除法放大。
**建議至少 40 個單位**；夾爪用它自己的兩個機械極限（見 §4）。

## 4. 每個關節的兩個姿態怎麼擺（🔴 最關鍵的一節）

**原則：姿態必須「物理上無歧義」**——也就是不靠眼睛估、可以用量角器或水平儀驗證的姿態。
「看起來差不多水平」不算，要量到。

| 關節 | URDF 軸 | 姿態 A | 姿態 B | 怎麼驗證 |
|---|---|---|---|---|
| `shoulder_pan` | Z（偏航） | 手臂指向墊子 **0°** 線 | 指向墊子 **−90°** 線 | 墊子上本來就印著角度線；把手臂中心線對齊 |
| `shoulder_lift` | Y | 上臂 **完全垂直** | 上臂 **完全水平** | 量角器／手機測角 app 貼在上臂連桿側面 |
| `elbow_flex` | Y | 前臂 **完全垂直** | 前臂 **完全水平** | 同上，貼在前臂連桿 |
| `wrist_flex` | Y | 腕段 **完全水平** | 腕段 **與前臂共線** | 共線用直尺靠著比較可靠 |
| `wrist_roll` | X（自轉） | 兩指連線 **水平** | 兩指連線 **垂直** | 手機測角 app 貼在夾爪平面 |
| `gripper` | — | **完全閉合**（兩指接觸） | **完全張開**（到機械停點） | 兩個都是機械極限，**不需要量角器**；用直尺量兩指開口 mm |

**夾爪特別說明**：它的兩個姿態是機械定義的，所以最可靠。
記錄「開口 mm」而不是角度——真正要的是 `讀數 → 開口` 的關係，因為模擬裡也是用這個判斷抓取。

⚠️ **每個姿態都要記錄「量到的物理值」和「手臂回報的讀數」兩個數字**，缺一不可。

⚠️ **擺姿態時關節要有扭力**（不要斷電讓它垂下），否則讀數是鬆掉之後的值，不是你量的那個姿態。

### 4-a. 量到的角度要填哪個數字（🔴 2026-09-21 新增，先讀這節再量）

**「上臂完全垂直」指的是「上臂那一節」指向正上方，不是整支手臂朝天，也跟「關節走到行程中點」無關。**
上臂 = `joint2`（shoulder_lift 軸）到 `joint3`（elbow_flex 軸）之間那一節。前臂 = `joint3` 到 `joint4`。

**參考框架來自 URDF**（`assets/omx_f/omx_f.urdf`），也就是模擬器載入的那個模型——
SCALE／OFFSET 最後要送進模擬，所以「真實關節角」只能用模擬吃的那個框架表達。
不是去模擬器裡跑出來的，是從 URDF 幾何算出來的。

`[已查證 2026-09-21]` URDF 裡 **26 個 `rpy` 全為 `0 0 0`**，沒有任何旋轉偏置，所以零位姿勢
完全由連桿向量決定：

| 連桿 | 向量（父→子） | 零位時的方向 |
|---|---|---|
| 上臂 `joint2→joint3` | `(0.0415, 0, 0.11315)` | **偏離正上方 20.14°（往前傾）** |
| 前臂 `joint3→joint4` | `(0.162, 0, 0)` | 正前方，**水平** |
| 腕段 `joint4→joint5` | `(0.0287, 0, 0)` | 正前方，**水平** |

#### 🔴 填表規則：從正上方量起，往前傾為正

**量「那一節連桿本身」相對於鉛垂線的角度，往前（遠離操作者）傾倒算正。**

- 連桿指向正上方 → 填 `0`
- 連桿水平指向正前方 → 填 `+90`

這條規則對每一節都一樣，不必記各自的零位。`[AI推論]` 對應到 URDF 關節角是：

| 關節 | 填的值（絕對角）與關節角的關係 |
|---|---|
| `shoulder_lift` | `填的值 = joint2 + 20.14°` |
| `elbow_flex` | `填的值 = joint2 + joint3 + 90°` |
| `wrist_flex` | `填的值 = joint2 + joint3 + joint4 + 90°` |
| `shoulder_pan` | 偏航，對墊子角度線量，不走這條規則 |
| `wrist_roll` | 自轉，對夾爪平面量，不走這條規則 |
| `gripper` | 填開口 mm，不是角度 |

```

   （目前校正：       +3.0 cm            17.3 cm            59°）
```

但**中間 50% 是 7.1–9.0 cm**（杯口 9.5 cm）。尾巴是 **7 集**，而那 7 集的 `episode_meta`
全都是 `outcome=success`、`quality=5`——不是失敗集，是**偵測器在那幾集挑到非抓取幀**

⚠️ **這仍是對「假設的目標值」做擬合**（高度 8.5 cm、朝下 85°、抓近側杯緣），是 `[AI推論]`。
**不要直接改常數。** 下一步是把 `(lift +18.2°, wrist_flex +7.1°)` 這組渲染出來給 Eric 看
——他已經否決過甲與乙，這是第三張圖，成本同樣是一次渲染。

#### 為什麼 SCALE 不受這個框架影響、OFFSET 受

**A 與 B 的差值把所有常數都消掉了**，所以只要 §4-b 的「A 到 B 之間其他關節不動」成立
（`--lock-others` 會強制），**SCALE 一定是對的**，不管你用哪個參考框架。

**OFFSET 不行**——它整個就是那個常數。上表右欄那些 `+20.14°`、`+90°`、以及上游關節的貢獻，
全部會被吸收進 OFFSET。**這就是 §6 `state_*` 六欄存在的理由：事後用同一份 CSV 就能扣掉，不必重量。**

⚠️ **所以量測當下不要試圖解 OFFSET。** 照上面的規則填絕對角、讓 `--lock-others` 鎖住其他關節、
把 `state_*` 記好，OFFSET 之後在軟體裡補正。

## 4-b. 怎麼把手臂擺到那些姿態（🔴 2026-09-21 新增）

`connect()` 結束時**扭力是開的**——`OmxFollower.configure()` 把寫入包在 `bus.torque_disabled()`
裡，而那個 context manager 的契約就是「guarantees torque is re-enabled」
（`lerobot/src/lerobot/robots/omx_follower/omx_follower.py:143`）。所以連上之後手臂是硬的，
**推不動**。擺姿態因此有兩條路，選一條：

### 路線甲：leader 帶動（有 leader 時用這條）

1. leader 與 follower 都接上、都通電
2. 跑遙操作，用 leader 把 follower 帶到 §4 的姿態
3. follower 扭力開著自己撐住 → 雙手空出來量角器貼上去驗證
4. 另開一個終端跑 `record --joint ... --pose ...`（不帶 `--reading`，讓它自己讀）

**這是 §4「擺姿態時關節要有扭力」原本設想的路線**，也是最穩的：手臂不會垮，量測時雙手是自由的。

### 路線乙：逐關節解鎖（只有 follower 時，**建議用這條**）

```bash
uv run python scripts/measure_joint_zeros.py session     --csv calibration/<日期>_joint_zeros.csv --lock-others
```

`--lock-others` **只放掉正在量的那一個關節，其他五個保持剛性**。換關節時才切換。

這條路把下面那個「A 到 B 之間其他關節不可以動」從**注意事項變成機械保證**——
其他關節被伺服器夾著，動不了。而且**手臂不會垮**，任何時刻最多只有一節的重量是鬆的。

🔴 **切換時腳本會先把其他關節的 `Present_Position` 抄進 `Goal_Position` 再開扭力。**
這一步不能省：對一個 `Goal_Position` 還停在舊目標的伺服器開扭力，**它會猛然彈到那個舊目標**。
抄過去等於「就停在你現在的位置」。兩邊都用原始 tick（`normalize=False`），不經過校正換算。

每個關節開始前會停下來：

```
--- shoulder_lift pose A: 上臂完全垂直
    🔴 about to release shoulder_lift -- it will drop. Every other joint stays rigid.
    support that link, then press Enter (q to quit):
```

**托住那一節再按 Enter。** 然後：擺到姿態 → 用量角器／直尺照 §4 驗證 → 輸入量到的值 →
**讀數回顯出來之前不要放手**（編碼器是在那一刻才讀的）。

### 路線丙：整支放鬆（`--hand-pose`，不建議）

```bash
... session --csv <檔> --hand-pose
```

連上之後**一次放掉所有關節**，要輸入 `yes` 確認。比路線乙鈍：**整支手臂會垮**，
而且其他關節的漂移沒有任何保護。留著是為了「想快速把整支擺成某個大致姿勢」的場合。
**量測本身請用路線乙。**

⚠️ 路線乙一個人做得來（其他關節撐著）；**路線丙實務上是兩人工作**。
**如果 leader 拿得到，走路線甲。**

### 🔴 三條路線都適用：量 A 和 B 之間，其他關節不可以動

joint2／3／4 **都繞 +Y**，角度會沿著鏈累加。量角器貼在前臂上量到的是**絕對俯仰角**
＝ `joint2 + joint3 + 常數`，不是 joint3 自己的角度。推論如下（`[AI推論]`，可推翻）：

| | 乾不乾淨 | 為什麼 |
|---|---|---|
| `shoulder_pan` | ✅ 乾淨 | 偏航只受 joint1 影響 |
| `shoulder_lift` | ✅ 乾淨 | 上臂俯仰只受 joint2 影響（joint1 是偏航，不改俯仰）|
| `elbow_flex` | ⚠️ 受 joint2 影響 | 絕對角 = j2 + j3 |
| `wrist_flex` | ⚠️ 受 j2、j3 影響 | 絕對角 = j2 + j3 + j4 |
| `wrist_roll` | ⚠️ 參考面受上游影響 | 手腕自轉軸被上游俯仰帶歪時，「兩指連線水平」不再是乾淨的參考 |
| `gripper` | ✅ 乾淨 | 量的是開口 mm，與手臂姿勢無關 |

**實務規則：**

1. **同一個關節的 A 與 B 之間，其他關節一律不要動。** 這樣 `Δ絕對角 = Δ該關節角`，
   **SCALE 是對的**（除法把共同的常數消掉了）。
   → **路線乙的 `--lock-others` 就是用伺服器強制這一條**，不必靠人記得。
2. **OFFSET 沒有這個保護**——它會把上游關節的貢獻吸收進去。
3. 所以 §6 的 `state_*` 六欄要填：**事後能用它把 OFFSET 補正回來，不用重量。**

⚠️ **不論哪條路線，斷線時扭力都會被放掉**（`disable_torque_on_disconnect` 預設 `True`）。
`session` 結束時會印紅字提醒，放手前先托住或降到休息姿勢。

## 6. 輸入／輸出

**量測記錄（CSV，人填或腳本產生）：**

```csv
joint,pose,physical_deg,physical_mm,reading,note,state_shoulder_pan,state_shoulder_lift,state_elbow_flex,state_wrist_flex,state_wrist_roll,state_gripper
shoulder_lift,A,90.0,,-61.4,上臂完全垂直,1.0,-61.4,12.5,3.0,0.5,47.4
shoulder_lift,B,0.0,,-6.4,上臂完全水平,1.0,-6.4,12.5,3.0,0.5,47.4
gripper,A,,0.0,47.4,完全閉合,1.0,-6.4,12.5,3.0,0.5,47.4
gripper,B,,34.0,59.6,完全張開到機械停點,1.0,-6.4,12.5,3.0,0.5,59.6
```

- **十二個欄位，順序固定**（`scripts/measure_joint_zeros.py` 的 `FIELDS`）。
- 🔴 **`state_*` 六欄是 2026-09-21 新增的：每一列都記下當下「整支手臂」的讀數**，不只是正在量的
  那一軸。原因見 §4-b 的累加問題——只要事後發現 OFFSET 需要扣掉上游關節的貢獻，用同一份 CSV
  就能重算，**不必重量**。用 `record --reading` 手動給值時這六欄會是空的（腳本會提醒），
  **盡量讓腳本自己讀**。舊的六欄 CSV 仍然可以 `solve`，`record` 也會沿用它原本的表頭不寫壞它。
  🔴 **2026-09-21 更正：本節原本的範例少了 `physical_mm` 欄，而且把夾爪寫成 `physical_deg=0.0`**，
  跟 §4「夾爪不量角度、量開口 mm」自相矛盾。照舊版手填的 CSV，`solve` 會回報
  `gripper: 1 usable pose(s), need 2`。
- `physical_deg`：量到的真實關節角（度）。**夾爪這欄留空。**
- `physical_mm`：**只有夾爪填**，直尺量到的兩指開口（mm）。其餘關節留空。
- `reading`：手臂當下回報的值（`observation.state` 的該通道）
- 用 `record` 子指令產生 CSV 就不會弄錯欄位；手填的話自己對照上面六欄

**輸出**：可直接貼進 `sim/joint_mapping.py` 的常數區塊。
