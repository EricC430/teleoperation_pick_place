# S8 — pan 軸在座標紙上的位置，以及 pan 的零點與比例（實機，指尖畫圓）

**目標腳本：`scripts/measure_pan_circle.py`**（`session` / `solve` / `selftest`）
**建立 2026-10-08。** 方法是機器人運動學校正常用的「圓點分析」（circle point analysis）：一次只轉一個關節，追蹤末端上的一個點，它畫出的圓會給出那個關節的轉軸。

> 這份設計成可以單獨帶到實驗室筆電執行。

---

## 1. 要解什麼問題

模擬的世界座標＝座標紙座標，杯子、ArUco 相機外參和擺放點全都用座標紙座標。模擬把手臂的 pan 軸放在座標紙原點 (0, 0)。

**這個假設從來沒有直接量過。** 10/08 的 `paper_to_pan` 擬合（`docs/meeting/2026-10-08_paper_to_pan.md`）量到的是：

| 關係 | 結果 |
|---|---|
| 座標紙 ↔ **FK 算出的** pan 座標系 | 偏差在約 1 cm 以內，信賴區間包含 0 |
| 座標紙 ↔ **實體** pan 軸 | 沒量過 |

兩者的差別在於：關節零點是 9/22 讓指尖碰座標紙上的點擬合出來的。如果實體底座其實偏了一點，這個偏移會被**吸收進 lift、elbow 的零點**，讓指尖仍然碰得到紙上的點，於是 FK 和座標紙看起來一致。
這種補償只在靠近桌面時成立，也是「高處對不上」的可能原因之一（`推論`）。

**S8 直接量實體 pan 軸在座標紙上的位置，而且結果不經過其他任何關節的零點。**

---

## 2. 原理

- lift、elbow、wrist_flex、wrist_roll 全部鎖住，只轉 pan。
- 夾爪尖端在紙面上方畫出一個**以 pan 軸為圓心的圓**。
  - 其他關節的零點如果錯了，只會改變圓的**半徑**，**不會移動圓心**。這就是這個方法不依賴其他校正的原因。
- 每停一站，讀出指尖正下方的座標紙座標 (x, y)，同時記錄 pan 的讀值 r。

```
(x_i, y_i) = c + ρ_k · (cos(φ_i + α_k), sin(φ_i + α_k)),    φ_i = s · r_i + o
```

| 符號 | 意義 | 來源 |
|---|---|---|
| `c` | **pan 軸在座標紙上的位置** | 擬合 |
| `s`、`o` | pan 的比例、零點（零點以座標紙的 x 軸為準） | 擬合 |
| `ρ_k` | 第 k 個圓的半徑 | 擬合；同時和 FK 的預測比較，當作 S7 的交叉檢查 |
| `α_k` | 指尖在手臂平面內的方位角（CAD 指尖偏離中線 1.65 mm，約 0.3°） | FK |

- **量兩個圓**，一個約 12–15 cm、一個約 22–25 cm：
  - 兩個圓心應該重合。不重合代表 pan 軸不是鉛垂的，或讀數有問題。
  - 半徑差得多，也讓零點 `o` 估得更準。
- **每一站都從同一側到達**：先轉到第一站再過去 3 單位，然後一路往同一個方向轉。這樣背隙對每一站的影響都一樣。
- 之後再**反向掃一次**，每隔一站讀一次，兩次的差就是 pan 的背隙。
- **pan 零點和底座的偏航角分不開**：兩者都是繞同一根軸的轉動。
  - 對模擬來說這沒關係，只要底座網格不旋轉、把整個角度都放在 pan 零點上即可（§5）。
  - 唯一的代價是底座網格在畫面上的朝向可能差一點，而底座不在 front-left 的畫面裡。

## 3. 需要的東西

- **硬體**：OMX follower（通電）、座標紙（就是放杯子的那張，**不要移動它**）、一支細的鉛筆（可選，用來在紙上點記號，事後複查）。
- **軟體**：實驗室筆電的 `uv` 環境；`solve` 和 `selftest` 任何有 numpy 的 Python 都能跑。
- **repo 檔案**：`scripts/measure_pan_circle.py`，以及它 import 的 `scripts/measure_link_tilt.py`、`reach_logger/fk.py`、`sim/joint_mapping.py`、`sim/omx_constants.py`。

## 4. 現場步驟

1. 清空手臂周圍 30 cm 內的東西：杯子、收納盒都移走，**座標紙不要動**。
2. 執行：
   ```bash
   uv run python scripts/measure_pan_circle.py session --csv calibration/<日期>_pan_circle.csv
   ```
3. 每個圓的流程：
   1. 腳本先把 pan 轉到起點，夾爪閉合。
   2. 腳本會**放掉 lift、elbow、wrist_flex**，pan、roll、夾爪保持出力。放掉前會先提醒你用手托住前臂和夾爪。
   3. 把夾爪擺成**尖端朝正下方、離紙面 3–5 mm、不要碰到紙**，扶著不要動，按 Enter，腳本就把這個姿勢鎖住。
   4. 腳本把 pan 轉到各站，預設 9 站、約 ±60°。每站停下來，你輸入**指尖正下方的座標 `x y`（cm）**，讀到 0.1 cm。
      - 讀的時候眼睛要在指尖正上方往下看，避免視差。
      - 如果其他關節跑掉超過 1 單位，腳本會警告。
   5. 反向掃描，每隔一站再讀一次。
4. 兩個圓量完，扭力保持開著。
5. 時間估計 1–1.5 小時，已經乘過 2–3 倍。原始估計約 30 分鐘：18 站加反向 10 站，每站約 1 分鐘。**請回報實際花了多久。**

⚠️ 和 S7 一樣，這支 `session` 只在假手臂上跑過完整流程（2026-10-08），還沒接過實機。

## 5. 求解與套用

```bash
python scripts/measure_pan_circle.py solve --csv calibration/<日期>_pan_circle.csv --date <日期>
```

`solve` 會印出：

- pan 軸在座標紙上的位置 (x, y)，附 95% bootstrap 區間。
- pan 的比例和零點。
- 各圓的半徑和 FK 預測的差（S7 的交叉檢查）。
- 兩個圓各自的圓心。
- 反向掃描量到的背隙。

最後印出要貼回去的值。**套用方式：**

| 結果 | 套用到 | 狀態 |
|---|---|---|
| pan 軸 `c` | 模擬裡把**手臂**整體平移 `c`；物體、ArUco 外參、擺放點維持座標紙座標 | 🔴 **還沒接進模擬**：`scene_constants.py` 目前沒有 `ARM_PAN_AXIS_IN_PAPER_M` 這個常數，渲染腳本也還沒讀它。量完再接 |
| pan 零點 `o`、比例 `s` | `sim/joint_mapping.py` 的 `shoulder_pan` | 由人貼回 |
| 腕部 T2（`sim/calib_extrinsics_aruco.py`） | 它目前假設手臂底座在座標紙原點，要改成用 `c` | 另一個 session 已發現它的 link0 位置有 bug，兩件事一起改 |

## 6. 驗收條件

- [ ] 擬合殘差 RMS ≤ 0.2 cm。這個標準是依讀座標的精度約 0.1 cm 訂的，`推論`
- [ ] 兩個圓各自的圓心相差 ≤ 0.3 cm
- [ ] pan 軸位置 95% 區間的半寬 ≤ 0.3 cm
- [ ] 量測 CSV 存進 `calibration/`，檔名帶日期，不覆寫

## 7. 明確不做、限制

- 只量平面（x、y、pan 角度）。底座高度沿用柏宇 10/07 量的墊高 14.6 cm。
- 不分開「pan 零點」和「底座偏航」（§2 最後一點）。
- 指尖不碰紙，是懸空讀座標，所以結果受視差影響。如果殘差 RMS 超標，改用鉛筆在指尖正下方點記號，量完再用尺讀記號。
- 假設 pan 軸是鉛垂的。S7 的 `base_x`、`base_y` 會量底座傾斜，兩個圓的圓心是否一致也能檢查這一點。

## 8. pan 和 wrist_roll 各由誰處理

| 關節 | 由誰量 | 怎麼量 |
|---|---|---|
