## 3. 紙杯的「人類示範下限」與它的定義問題

`scripts/open_loop_floor.py`（本次新增；定義照 D031 §3），輸出 `outputs/open_loop_floor/*.txt`。

| 預測器（N=100，每集平均） | 紙杯 eval 12 集 |
|---|---|
| freeze | 13.92 |
| 任取另一集 eval 示範（中位數） | 9.82 |
| oracle：11 條其他 eval 示範中挑最合的 | 6.64 |
| oracle：12 條訓練示範（ep 0,5,…,55） | 6.79 |
| oracle：60 條訓練示範 | **4.57** |
| oracle：12 條訓練示範，donor 時間長度拉齊（`--align timenorm`） | 6.11 |
| policy `2bdff2b3871e` / `e6ef7c0e9528` | 6.23 / 6.68 |

**「下限」不是一個固定數字** `[已查證]`：候選從 12 條增為 60 條，6.79 → 4.57；對齊方法換掉，6.79 → 6.11。
鋁罐同樣成立（12 條 7.79 → 56 條 6.60）。
所以「policy 已達人類下限 → 指標飽和」要附上候選數與對齊方法才有意義。對 D031 的影響寫在 D031 §7。
