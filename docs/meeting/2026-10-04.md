## 3. 解讀的限制

- N 不同時，MAE 量的不是同一件事（09-29 紀錄 §1）。N=30 的 MAE 比較低，只代表**短距離預測比較準**。
- 開環時每次推論拿到的都是示範時的真實畫面，誤差不會累積。所以開環的結果**不能**直接推成「閉環 N=30 成功率較高」（09-29 紀錄 §3-5）。要驗證，就得跑下面的閉環 `[未確認]`。

## 4. 閉環 N=30 的指令（尚未執行）

```powershell
uv run lerobot-rollout --config_path configs/rollout_omx_b4a_plastic_bottle_100k_eval.yaml --policy.path=ericc430/act_omx_b4a_plastic_bottle_100k --policy.n_action_steps=30 --dataset.repo_id=ericc430/rollout_omx_b4a_plastic_bottle_100k_nas30
```

⚠️ **`--policy.path=` 一定要在指令列上重寫一次**（2026-10-05 更正，原本這行沒有）。少了它會出現
`error: policy: ... Expected a dict with a 'type' key ..., got {'n_action_steps': 30}`（柏宇 10-05 跑鋁罐 40k 時遇到）。
原因 `[已查證]`：`lerobot/src/lerobot/configs/parser.py` 的 `wrap()` 先呼叫 `filter_path_args()`，之後才呼叫
`extract_path_fields_from_config()`。所以 `policy.path` 只寫在 YAML 時，`filter_path_args()` 看不到它，
`--policy.n_action_steps` 不會被濾掉，直接交給 draccus 去解析。
在指令列重寫 `--policy.path` 之後，不連手臂只跑參數解析，得到 `n_action_steps=30` `[已查證]`。
另一種做法：在 YAML 的 `policy:` 底下加 `n_action_steps: 30`（走 `_config_yaml_overrides`，讀過程式碼，沒有實測）。

讀原始碼確認過，參數解析成功之後，這個設定會生效 `[已查證]`：
- `lerobot/src/lerobot/rollout/configs.py`：設了 `policy.path` 時，`--policy.*` 會當成 `cli_overrides` 傳進 `PreTrainedConfig.from_pretrained`。
- `rollout/inference/sync.py` 走的是 `policy.select_action()`。`policies/act/modeling_act.py` 會把 chunk 切成 `[:, :n_action_steps]` 放進 queue，queue 用完才重新推論。
- `config_records` plugin 會把指令列覆寫寫進檔頭，所以這次 run 在 `config_records/` 會留下 N=30 的紀錄。

要注意的地方 `[推論]`：sync 模式下，每次重新推論都會卡住控制迴圈。N=30 時卡的頻率大約是 N=100 的 3.3 倍。3050 單次推論要多久 `[未確認]`。
