## 一、進度報告（8 分鐘）

### 1. GPU 訓練環境已可用（柏宇，3 分鐘）

- Docker 容器跑起來，`torch.cuda.is_available()` 為 True，4090 正常
- **過程中診斷並解決了一個非顯而易見的問題**：host driver 550.54.14 只支援到 CUDA 12.4，而官方 image 的 torch 要 12.8。NVIDIA 的 forward-compat 函式庫只支援資料中心卡（Tesla/A100/H100），在 GeForce 上會噴 `Error 804`。解法是兩個 flag 併用，缺一不可
- 環境已釘選：image digest + LeRobot 0.6.2 + torch 2.11.0+cu128，記錄於 `docs/environment.md`
- ⚠️ **這是 workaround 不是修復**。乾淨的解法有兩條，都需要老師協助：
  - **請實驗室管理者把 host driver 更新到 ≥570**（我們沒有 sudo）← **要老師拍板**
  - 或自建 CUDA 12.4 base 的 image（Dockerfile 尚未寫）

### 2. 訓練管線已在公開資料集上驗證（柏宇，2 分鐘）

### 3. 工作坊 GR00T 失敗的歸因分析（霆翰，3 分鐘）★ 全場最有份量的一頁

`experiment_spec.md` §9。重點不是「試了效果不好」，是**從症狀組合逐一淘汰假設、定位到 covariate shift、並據此改變了資料收集策略**（recovery demo 7:3）。
