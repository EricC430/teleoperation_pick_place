**查證過程** `[已查證]`：

- 10:39 每集第 0 幀的狀態是 wrist_flex **+1.5**、gripper **50.6**。訓練資料（`alcan60_fixed`，60 集第 0 幀）的範圍是 −15.4～−3.6 和 57.2～60.1，兩個都超出範圍。

- 柏宇用 `read_joint_pose.py` 讀出「目視正位」的角度：+1.5 / 50.6。拿腕部相機畫面去比對後，確認手臂姿勢**真的**和 9/20 不同。

  柏宇也說，扭力關掉時手臂並沒有靠在夾子上，而且這次執行過程中沒有撞到。

**機制** `[已查證]`：`reset_to_initial_position` 回到的是**連線那一刻**的姿勢（`rollout/context.py:331`）。
程式結束時會關扭力（`disable_torque_on_disconnect`），手臂就停在放鬆後的位置，下一次啟動時拿這個位置當起點。
**所以起始姿勢是「手臂上次被放在哪裡」，從來沒有被固定過。** 所有 rollout 的 ep 0 第 0 幀 `[已查證]`：

**影響**：過去跨 session 的比較（例如 9/18 紙杯 vs 9/21 鋁罐），起始姿勢都沒有被控制，是被動繼承上一次留下的位置。

**修正**：啟動 rollout 前先跑 `uv run python scripts/read_joint_pose.py --goto-home [--home cup]`。
這一步會開扭力、花 3 s 把手臂移到 HOME，並且**不關扭力**。

rollout 連線時 `configure()` 會短暫關扭力，手臂會下垂一點。

## 2-c. E3 離線：相機偏移敏感度（2D 影像變換）`[已查證]`

`scripts/eval_open_loop.py` 新增 `--image_affine CAM:DX,DY,ROT_DEG[,SCALE]`。
模型 `act_omx_b1_uvc60_100k`（`2bdff2b3871e`）；資料 eval-open 12 集，相機在 A2。原始資料在 `outputs/e3_cup_100k/`（含 `run.sh`）。
A2→B 的變換：用桌緣交界線的角度和高度，加上木紋位置擬合而得，結果為 +4.4°、(−14.4, +13.9) px。疊圖驗證過桌緣和貼紙重合，手臂則對不上，因為有視差或底座移動。

| 條件 | MAE | Δ | 變差集數 |
|---|---|---|---|
| N=100 對照組 | 6.227（09-29 在 5090 上是 6.23） | — | — |
| A2→B | 6.821 | +0.59 | 10/12 |
| 近似今天的位置（A2 → A1 附近） | 6.817 | +0.59 | 9/12 |
| dx 15 / 30 | 6.32 / 6.50 | +0.10 / +0.27 | 7 / 7 |
| dy 15 / 30 | 6.29 / 6.51 | +0.06 / +0.28 | 9 / 8 |
| 旋轉 2.2° / 4.4° | 6.59 / 6.30 | +0.36 / +0.07 | 8 / 6 |
| N=30 對照組 / N=30 + A2→B | 4.381 / 4.524 | +0.14 | 8/12 |

- 相機偏移對 open-loop 的影響（≤ +0.6），約是 N 100→30（−1.85）的 1/3。N=30 時影響更小（+0.14）。
- 「近似今天的位置」也增加了 +0.59，旋轉的效果也不是單調遞增，所以影像變形本身就帶有約 0.3–0.6 的影響。
  這個方法**分辨不出 A1 和 B 誰比較好** `[AI推論]`。
- 影響的方向符合幾何：水平平移時主要是 pan 變差，垂直平移時主要是 lift／elbow 變差。
  這表示模型會用第三視角畫面中的位置來決定伸手的方向和距離 `[AI推論]`。
- 限制：2D 變換模擬不了視差。open-loop 的 MAE 也不等於閉環成功率。
