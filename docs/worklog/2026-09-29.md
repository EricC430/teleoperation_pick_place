## 1. 做了什麼

- `scripts/eval_open_loop.py` 新增 `--n_action_steps N`：open-loop 時每 N 幀才重新推論一次（ACT 預設 100 = `chunk_size`）。
  `metrics.json` 會記下 `n_action_steps`、`n_action_steps_overridden`，以及權重 hash `weights_sha256_12`。
- 新增 `docs/models.md`：權重 hash ↔ 本機 run/step ↔ Hub repo ↔ 物品 ↔ 閉環用過哪次。
  起因：分不清閉環用的是哪個模型；最後是靠 Windows 上的 `config_records/` 加 hash 比對才確認 `[已查證]`。
- 用閉環用過的 checkpoint 跑 open-loop，每個 checkpoint 各跑 N = 100／50／20。

**MAE 的定義**：`mean |pred_action − gt_action|`，對全部幀、6 個關節取平均，單位是 LeRobot `.pos`（不是度數）。
⚠️ **N 不同時，MAE 衡量的東西就不同**：第 t 幀的預測來自 ⌊t/N⌋·N 那一幀，所以 N 越大，要往未來猜得越遠。
跨 run 比較時，N 必須相同。

## 3. 解讀

1. **推論間隔的影響遠大於訓練步數** `[已查證]`。在 eval-open 上，N 從 100 降到 20，MAE 降了 40–56%（全部 8 個 checkpoint）；
   同一個 N 下，不同 checkpoint 之間的差距不到 0.6。
2. **N 小 MAE 就低的機制，目前只是推論**：「猜得越遠錯得越多，N 小就砍掉遠的那一段」是最直接的解釋，
   但上面誤差 vs k 的表混入了任務階段，**不能拿來證明這一點**（本段原本寫成 `[已查證]`，已更正）。
   訓練集上 N 幾乎沒有影響 `[已查證]`，這和這個解釋一致，但也還不能算證明。
3. **多訓練沒有改善沒看過的位置** `[已查證]`：同一個 N 下，三個物品的 checkpoint 之間都差不多，
   和 2026-09-19 在 `alcan60` 上看到的 20k/40k/100k 都約 8 一致。
   趨勢的方向不一致：寶特瓶在 N=100 時步數越多越高（約 5%），紙杯則是步數越多越低（約 4–7%），
   兩者都在同一個物品內部的集與集差異範圍內 → 看不出一致的 overfit 或持續改善。
4. **物品難度（N=100）**：紙杯約 6.3 < 鋁罐約 7.4 < 寶特瓶約 10。`[推論]` 但三者的 eval-open 集長度差很多
   （平均 211／317／465 幀），集越長，N=100 時遠距離猜測的比例就越高，所以這個排序不能直接當成物品難度。
5. **這些都是 open-loop**：每次推論拿到的都是人類示範的真實畫面，錯誤不會累積。
   N 小 MAE 就低，**不能**直接推成「閉環把 N 調小會更好」；閉環時頻繁推論的作用是讓模型修正自己的偏差，
   但也可能在 chunk 交接處造成抖動或換策略。要驗證就得跑閉環 `[未確認]`。
