5. **起點從哪來**：今天的相機離 10/14 那個約 18 cm、22°（在手臂底座座標下比），比收斂範圍大很多，所以不能從 10/14 的相機出發。起點用 10/18 ArUco v2 的相機，經 `2026-10-29_fl_markerless.md` §2 的「座標紙↔底座」換到手臂座標（`start_from_v2.py`）。解跟這個起點差 8.8 mm、1.72°：可能是換算誤差（§2 的 yaw 隨手畫線 ±2.5°），也可能 10/18 之後相機又動過，**分不出來** `推論`。

## 1. 做法

- 手臂參數（底座、關節 offset、sag）固定在 `calibration/2026-10-29_fl_markerless/arm_fit_H2.json`（10/14 有標記的資料擬合）。成立前提是 10/14 之後底座沒動、沒重新校正舵機（現場紀錄：EricC430 口頭確認＋校正檔清單）。
- 其餘同 `2026-10-29_fl_markerless.md` §5：完整 URDF mesh 的外輪廓 → 沿法線找內暗外亮的邊 → 點到線最小平方解相機 6 自由度。這次沒有標記，不用遮罩（只遮 4 px 邊框）。
- 拍到的手臂上有 CAD 沒有的東西：夾爪上方一圈黑色線材、前臂下方藍白橘的零件。疊合圖上前臂下緣那排凸起有對上（`overlays.jpg`，綠＝擬合後、紅＝起點），線材圈沒有造成可見的偏移，但沒有量化 `推論`。

## 3. 給 sim 用的相機

`calibration/2026-10-29_fl_cad_field/camera_cad_field.json`：

- 對應的手臂參數就是 `arm_fit_H2.json`；sim 要對得上，手臂也要用同一組 offset／sag `推論`。

## 4. 重跑

```bash
F=calibration/2026-10-29_fl_cad_field
python3 $F/start_from_v2.py                     # 起點（寫 $F/start_v2.json）
C="--arm-from calibration/2026-10-29_fl_markerless/arm_fit_H2.json --captures calibration/2026-10-29_fl_cad_before_captures.csv \
   --excluded $F/none.csv --screen calibration/shots/2026-10-29_fl_cad_before_screen.csv --start-camera $F/start_v2.json \
   --gate-start 30 --rounds 14"
python3 scripts/fit_camera_from_cad.py $C --split-check --out $F/camera_cad_field.json   # 主結果（之後加 link0_from_camera）
# 唯一性：加 --perturb-camera-init 2,1 或 5,3 --perturb-seed 0..3；張數：加 --max-stills 10/20/40 --perturb-seed 0..2
python3 $F/summarize.py <放各組 .json/.txt 的資料夾，要有 g30.json>
```

`none.csv` 不存在是刻意的：不排除任何照片（`--screen` 已經篩過）。
